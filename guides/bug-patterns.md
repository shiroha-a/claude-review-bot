# バグパターン集（レンズ A / C / D / E / F）

各レンズを hunk ごとに当てる。項目は「この形があれば必ずバグ」ではなく「この形を見たら、壊す入力を 1 行書けるか試す」ためのもの。
書けなければ反証の段階で落ちる。書けたら候補に残す。

## A. 意図と論理

**意図とのズレ**

- PR 説明・関数名・コメント・テスト名が言っていることと、コードが実際にやっていることが違う
- 「〜の場合だけ」のはずの処理が無条件に走る／その逆
- 追加された分岐で、既存の分岐の前提（ソート済み、非 nil、長さ > 0 等）が崩れる
- 新しい列挙値・状態・エラー種別を追加したが、switch/match/if チェーンの全箇所に追加されていない（`default` が黙って飲み込む）

**境界と比較**

- `<` と `<=`、`>` と `>=`、`len-1` と `len`、ページングの `offset/limit` 計算、「含む/含まない」の端
- ループの終了条件が変更後のデータ構造と合っていない（要素削除しながらの走査、イテレータ無効化）
- 空のコレクションで最初の要素を取る、`max`/`min` の初期値が 0 で負の値を取りこぼす
- 範囲チェックが片側だけ（`x > 0` だけで上限なし、`i < n` だけで負を通す）

**条件の誤り**

- 否定の取り違え（`!a || !b` vs `!(a && b)`）、ド・モルガン
- 短絡評価に依存した副作用（右辺が実行されない）
- 等価比較の種類（参照 vs 値、`==` vs `===`、浮動小数点の `==`、大文字小文字、末尾空白、Unicode 正規化）
- 文字列比較で `"10" < "9"`

**コピペ・取り違え**

- 似た 2 ブロックで片方だけ変数名が直っていない（`start` を使うべき所で `end`、`src` と `dst`）
- 戻り値を変数に入れたのに使っていない／古い変数を使い続けている
- 引数の順序（`(a, b)` と `(b, a)`、特に同じ型が並ぶ関数）
- 単位の混在（秒/ミリ秒、バイト/KB、度/ラジアン、税込/税抜、UTC/ローカル）

**制御フロー**

- 早期 return / continue / break がクリーンアップ・ロック解放・カウンタ更新を飛ばす
- `finally`/`defer` の中で例外・エラーが上書きされる
- 例外を catch して処理を続けるが、続けられる状態ではない
- フォールスルー（switch の break 忘れ、Go の `fallthrough`）
- 再帰の終了条件が入力によって到達しない

**データの整合**

- 複数の場所で同じ情報を保持していて片方だけ更新（キャッシュと本体、カウンタと実体、索引と配列）
- 部分更新（3 フィールド中 2 つだけ更新して整合性が崩れる）
- ソート・重複排除・フィルタの順番が結果を変えるのに順番が変わった

## C. 状態・時間・並行性

**共有可変状態**

- グローバル変数、シングルトン、パッケージレベルの map/slice/リスト、クラスの static フィールドへの書き込み
- リクエスト間で共有されるオブジェクト（ハンドラ構造体のフィールド、ミドルウェアの状態）にリクエスト固有の値を書く
- 複数の goroutine / スレッド / async タスクが同じ map・配列・構造体を読み書き（Go の map、Java の非 synchronized なコレクション）
- クロージャが外側のループ変数を捕捉（言語バージョンによって挙動が違う）
- **モジュールレベルの既定値・定数オブジェクト**（`DEFAULT_*`、`defaultConfig`、クラス属性の dict/list）が参照のまま渡され、呼び出し先で破壊的に変更される。特に **浅いコピー**（スプレッド `{...x}`、`Object.assign({}, x)`、`dict(x)`、`copy.copy`、スライスのコピー）をしてから **深いマージ・ネストの書き換え** に渡す形: トップレベルは別物でもネストしたオブジェクトは共有されたままなので、1 リクエストの変更が全リクエスト・全ユーザーに漏れる。「既定値を取る関数」が毎回新しいオブジェクトを返すか、同じ参照を返すかを確認する
- キャッシュ・プールから取り出したオブジェクトを変更して戻す（次の利用者に変更が見える）

**原子性**

- read-modify-write（`balance = balance - x`、`count++`、`if !exists { create }`）がロックやトランザクションなしに行われる
- 「存在確認 → 作成」「残高確認 → 減算」「ファイル存在確認 → 開く」の間に状態が変わりうる（TOCTOU）
- check-then-act を DB の UNIQUE 制約や `SELECT ... FOR UPDATE`、CAS で守っていない
- 複数のストア（DB + キャッシュ、DB + キュー、2 つのテーブル）への書き込みが片方だけ成功しうる

**ロック**

- ロックの範囲が狭い（取得・解放の間に守るべき操作が入っていない）／広すぎてデッドロック・I/O を抱える
- ロック順序が場所によって違う（デッドロック）
- 読み書きロックで、書き込み経路が読みロックだけ取っている
- ロックしたまま return する経路（defer/finally で解放していない）
- 再入不可のロックを同じスレッドが再取得

**非同期・ライフサイクル**

- 起動した goroutine / Promise / Future / スレッドが終了する条件がない（キャンセル・タイムアウト・close を待っていない）
- `await` 忘れ、Promise の fire-and-forget、エラーハンドラなしの非同期タスク
- コールバックが複数回呼ばれる／一度も呼ばれない経路
- チャネルの close を複数箇所で行う、close 済みチャネルへの送信、受信側がいないチャネルへの送信でブロック
- タイマー・ティッカー・サブスクリプションの停止忘れ

**時間**

- `time.Now()`／`Date.now()` をロジックの途中で複数回呼び、間に時間が進む前提が崩れる
- タイムゾーン・DST・うるう秒・月末日（1/31 + 1 month）
- 有効期限の比較が `<` か `<=` か、期限切れの瞬間の扱い
- 単調時計 vs 壁時計（経過時間の計測に壁時計を使う）
- リトライ: 無限リトライ、バックオフなし、冪等でない操作のリトライ（二重課金・二重送信）

**順序と冪等性**

- イベント・メッセージが順不同／重複で届く可能性を無視
- 冪等キーがない、または生成がランダムでリトライごとに変わる
- 初期化順序（まだ初期化されていないものを参照、`init` の相互依存）

## D. エラーとリソース

**エラーの扱い**

- 戻り値のエラーを無視（Go の `_ =`、`err` を受けて使わない、Python の裸 `except: pass`、JS の空 `catch`）
- エラーを握りつぶしてデフォルト値で続行（`0`、`""`、`null`）し、下流がそれを正常値として扱う
- エラーをログに出すだけで呼び出し元に返さない（呼び出し元は成功したと思う）
- 例外を catch する範囲が広すぎて、想定外の例外（プログラムのバグ）まで「正常なエラー」として処理される
- エラーの型・メッセージで分岐しているが、新しい経路のエラーが一致しない
- 部分的失敗: ループの途中で失敗したとき、処理済みの要素をどうするか決まっていない（ロールバックなし、再開不能）
- エラー情報の欠落（元のエラーをラップせず捨てる、スタックが失われる）

**クリーンアップ**

- open/acquire したものを **全経路** で close/release しているか（early return、例外、panic、`continue`）
- ループ内で `defer`（関数終了まで解放されない）
- 二重 close、close 済みリソースの使用
- トランザクションが commit も rollback もされない経路
- 一時ファイル・ロックファイル・PID ファイルの削除忘れ

**無制限**

- 外部入力で決まるサイズ（配列長、ページサイズ、アップロードサイズ、ヘッダ数、JSON の深さ）に上限がない
- 入力をすべてメモリに読む（`io.ReadAll`、`file.read()`、`JSON.parse` on body）でサイズ制限なし
- キュー・キャッシュ・map が増えるだけで減らない
- 正規表現が入力に対して指数時間（ReDoS: ネストした量指定子 `(a+)+`、`(.*a){n}`）
- 再帰・ループの深さが入力に比例し、スタックや時間を食いつぶす
- 外部呼び出し（HTTP、DB、gRPC、subprocess）にタイムアウトがない
- コネクションプール・ワーカー数の上限がない／上限があるが解放されず枯渇

**プロセスとシステム**

- シグナル・シャットダウン時に処理中の仕事がどうなるか
- 設定の不在・不正値のとき、落ちるのか黙って既定値で動くのか（本番で黙って既定値は事故）
- ディスクフル・権限不足・ネットワーク断の扱い

## E. 境界とデータ

**値の極端**

- null / nil / undefined / None（Optional の中身、map のゼロ値、JSON の欠落キーと null の区別）
- 空文字列・空配列・空 map・空ファイル・0 件の DB 結果
- 0、負数、最大値、`-1`（番兵値として使われているか）
- 巨大値: `2^31`、`2^53`（JS の安全整数）、`2^63`、ミリ秒タイムスタンプ、ファイルサイズ
- 浮動小数点: `NaN`（比較が常に false）、`Infinity`、`-0`、金額計算での誤差
- 整数: オーバーフロー、符号付き/符号なしの変換、切り詰め（`int64 → int32`、`int → uint8`）、除算の切り捨て、ゼロ除算、`%` の負数

**文字列とエンコーディング**

- Unicode: 結合文字、サロゲートペア、絵文字（`len` が文字数ではない）、正規化（NFC/NFD）、大文字小文字変換の言語依存（トルコ語の i）
- 不正な UTF-8、NUL バイト、制御文字、BOM
- 末尾の改行・空白、CRLF/LF
- 文字列のバイト長 vs 文字数 vs 表示幅（DB の VARCHAR(n) は何の単位か）
- 数値の文字列化・パース（先頭 0、`+`、`1e3`、`0x`、ロケール依存の小数点）

**型と変換**

- 動的言語での暗黙の型変換（`"1" + 1`、`[] == false`、Python の `if x:` で 0 と None と空を区別しない）
- JSON: 数値が float に化ける（大きな整数の精度落ち）、`undefined` が消える、キーの重複
- 列挙値を文字列・整数で受け取り、未知の値の扱いが決まっていない
- 日付の文字列パース（フォーマット・タイムゾーン未指定）

**契約の変更**

- 関数のシグネチャ・戻り値・エラー条件・nil 許容が変わったのに呼び出し元が追随していない（動的言語・リフレクション経由・別リポジトリの呼び出し元に注意）
- 構造体・クラスのフィールド追加/削除/型変更で、シリアライズ形式（JSON、protobuf、DB 行、キャッシュ）の互換性が壊れる。古いデータを読めるか、古いバージョンが新しいデータを読めるか（ローリングデプロイ中の混在）
- DB マイグレーション: NOT NULL 追加でデフォルトなし、型変更でデータ損失、インデックスなしでの大テーブル変更、ダウンマイグレーションの有無、アプリの新旧どちらと互換か
- 公開 API のレスポンス形式・ステータスコード・エラー形式の変更
- 設定キー名・環境変数名・CLI フラグの変更
- デフォルト値の変更（既存ユーザーの挙動が黙って変わる）

## F. テストと観測性

**テストの実効性**

- 変更でリスクが高い経路（エラー分岐、境界値、認可失敗、並行実行）にテストがない
- assert が無い／常に真（`assert True`、`expect(x).toBeDefined()` だけ）
- テストが変更された: 期待値が「実装の出力」に合わせて書き換えられていないか（バグを固定化するテスト）
- モックが本物と違う挙動（エラーを返さないモック、順序を無視するモック）
- テストが時刻・乱数・環境・実行順序に依存してフレーク
- 削除・スキップされたテスト（`skip`、`xit`、`t.Skip`、コメントアウト）

**観測性**

- ログ・エラーメッセージ・例外・メトリクスに秘密情報（トークン、パスワード、鍵、Cookie、Authorization ヘッダ）や PII が入る（構造体ごとダンプしている箇所に注意）
- 失敗が黙って起きる（ログもメトリクスもない）ため本番で気づけない
- ログレベルが不適切（エラーが debug、通常処理が error でノイズ）
- 外部入力をそのままログに書く（ログインジェクション、改行で偽ログ行）
